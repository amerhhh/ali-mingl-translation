Task:
We need to optimize the display of chat messages by rendering only one message at a time, and ensuring that the corresponding emoji is shown next to the message.

Details:

Input: The message object contains fields sourceText, targetText, and user_emoji for each message.

Output: The chat interface should display only the current message with the corresponding emoji next to it, and it should be optimized for rendering just one message at a time.

Code to Implement:

tsx
Copy
// Message Component: Render a single message with emoji next to it
const Message = ({ message, onPlayTranslation, isSpeaking, uiText }) => {
  return (
    <div className="flex items-center space-x-2">
      {/* Render emoji next to the message */}
      {message.userEmoji && (
        <span className="text-xl">{message.userEmoji}</span>  {/* Display emoji */}
      )}
      <div className="message-content">
        {/* Display the original source text */}
        <p>{message.sourceText}</p>
        {/* Display the translated text (if available) */}
        {message.targetText && <p className="text-muted">{message.targetText}</p>}
      </div>
    </div>
  );
};

Explanation of the Code:

Rendering One Message:
The Message component is optimized to render only a single message at a time. We pass a single message object to the component, and it only renders that message with the emoji and translation if available.

Emoji Rendering:
The emoji (userEmoji) is displayed next to the message in the text-xl size. If the userEmoji exists, it will be shown; otherwise, it will be skipped.

Message Content:

The sourceText (original message) is displayed.

If there is a translated message (targetText), it is displayed below the original message in a muted style (text-muted class).

Optimization:

This approach ensures that only the current message is rendered, and you do not have to re-render the full page or all the messages every time.

This helps in optimizing performance, especially for chat applications where new messages are frequently added.
